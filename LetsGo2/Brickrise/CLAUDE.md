# 브릭라이즈 (Brickrise)

고객이 사진 1장을 올리면 그 피사체를 1x1 큐브 블럭으로 재현한 맞춤 조립 키트를 만들어 파는 서비스.
네이버 스마트스토어에서 판매하고, 시안 생성은 브릭라이즈 자체 사이트에서 한다.

이 파일은 claude.ai 대화(2026년 10~11월)에서 정한 내용을 정리한 것이다. 법률 관련 항목은 아직 변호사 자문 전이다.

## 확정된 결정

### 블럭
- MYTOYS 디폼블럭 (국내 유통, 부품 KC 인증): 1x1 큐브, 8 x 8 x 7mm, 옆면 결합, 윗면 돌기 1개
- 1,000개당 약 2,100원 (개당 약 2.1원)
- 39색. 자동 배색은 36색, 투명색·야광색·투명야광색(33·34·39)은 제외 → `prototype/pal39.py`
- 내부는 채운다 (옆면 결합으로 전체가 한 덩어리, 떨어지는 조각 없음)
- 크기 5 / 10 / 15cm (가로 기준 약 6 / 12 / 18칸)
- 요고요(레고 호환)·중국산은 검토 후 제외

### 형태
- 평면: 사진을 그대로 픽셀 아트로 (3D 생성 없음)
- 입체: 사진 → 상용 image-to-3D API → 복셀화 → 디폼블럭 배치
  - 품질 테스트: TripoSR은 품질 부족, TRELLIS.2는 우수. 실서비스에는 상용 API 사용 예정 (업체 미정)
  - 배경 제거(누끼)는 생성 로직 안에서 자동 처리. 고객에게 안내하지 않음

### 고객 흐름 (로그인 없음)
1. 네이버 스토어 상세페이지 → '내 브릭 만들기' 링크
2. 형태·크기 선택
3. 사진 올리기 전 동의 (사이트): 개인정보 수집·이용, 국외 이전, 사진 권리 보증, 만 14세 이상 (필수) + AI 이미지 활용 (선택)
4. 사진 1장 업로드 → 품질 자동 검사 (밝기·흐림·피사체 크기·해상도) → 무료 횟수 확인 → 시안 생성
5. 시안 확인: 이미지("AI 생성 예시" 표시), 크기, 총 블럭 수, 가격. 색상별 부품 목록은 결제 후에만 제공
6. 주문 코드 발급 → 네이버에서 옵션·수량·코드 입력 후 결제
7. 주문 코드 검증 → 피킹 → 설명서 PDF 생성·QR 안내지 → 포장 → 발송
8. 고객은 QR로 PDF 설명서를 열어 조립. 부족·문의는 네이버 톡톡

자세한 흐름: `docs/flow_detail.html`, 요약: `docs/flow_simple.html`, 동작하는 시연: `docs/demo.html`

### 동의 위치
- 사이트에서 받는 것 (사진 받기 전): 개인정보 수집·이용, 국외 이전, 사진 권리 보증, 만 14세 이상, (선택) AI 이미지 활용
- 네이버 상품 페이지·주문서에서 고지: 주문제작 청약철회 제한, 시안과 실물 차이
- 사진은 브릭라이즈가 직접 받으므로 사이트 동의를 네이버로 넘길 수 없다

### 가격
- 총액 = 기본 제작비(형태·크기) + 블럭 수 × 블럭 단가
- 네이버: 옵션 6개(평면/입체 × 5/10/15cm) = 기본 제작비, 추가상품 '블럭 10개' 수량 = ceil(블럭 수 / 10)
- 원가: 안내지 100 + 박스 1,000~2,500 + 택배 3,500 + 생성형 AI·서버 비용 3,000(주문 1건당 설계값, Vercel 등 서버비 포함, 형태 구분 없이 적용) + 블럭
- 인건비는 원가에서 제외 (초기에는 관리자 4명이 직접 포장·발송, 2026-11 결정)
- 판매가·단가는 미확정 (시연 페이지는 임시로 기본 제작비 + 블럭 1개당 10원)
- 배송비 3,000원 고객 부담 (임시, 2026-11). 결제 금액 = 기본 제작비 + '블럭 10개' 수량 × 100원 + 배송비. 주문 검증의 금액도 배송비 포함 금액으로 대조

### 주문 코드
- 형식 `BR-3D10-K7Q2`: 3D=입체 / 2D=평면, 05·10·15=크기, 뒤 4자리 무작위 (헷갈리는 문자 제외)
- 7일 유효, 1회용. 서버에 시안·블럭 수·옵션·금액과 함께 저장
- 결제 후 검증 4단계: 코드 존재·유효 / 옵션 = 코드의 형태·크기 / '블럭 10개' 수량 = ceil(블럭 수 / 10) / 금액
- 불일치 시 네이버 톡톡 안내: 옵션 불일치 → 취소 후 재주문, 수량 부족 → 차액 결제, 수량 초과 → 부분 환불
- 초기에는 운영자가 판매자센터에서 코드를 확인, 주문이 늘면 네이버 커머스 API로 자동화
- 관리자 주문 검증의 '네이버 주문번호'는 선택 입력으로 유지. 커머스 API 연동 시 자동 입력하도록 개발 (2026-11 결정)
- 검증 통과 시 고객 알림은 따로 보내지 않는다. 판매자센터에서 발주확인 → 고객 주문 상태 '상품준비중'으로 안내를 대신함 (2026-11 결정). 발송 처리(송장 등록) 시 배송 알림도 네이버가 보냄. SMS 미사용

### 무료 시안 횟수
- 쿠키(기기 표시) 기준 하루 3회 + IP 기준 하루 15회 정도의 넉넉한 상한. 둘 중 하나라도 넘으면 중지
- 품질 검사 불합격, 같은 사진·옵션 재생성은 차감 없음
- IP는 해시로 짧게만 보관. Redis는 횟수 카운터처럼 하루 지나면 사라져도 되는 값에만

### 설명서
- 종이 설명서 없음. 주문마다 PDF를 한 번 생성해 파일 저장소에 두고, QR 안내지 1장이 그 PDF로 연결
- PDF: 1쪽 완성 이미지 + 색상별 개수, 이후 층별 위에서 본 칸 지도 + 색상 번호 (흑백 인쇄 대비)
- 박스에는 KC 신고번호, 제조자 정보, 사용 연령, 작은 부품 경고를 반드시 인쇄 (QR로 대체 불가)

### 배송
- 결제 확인 후 2~5일 안에 제작·발송 (상세페이지·FAQ 안내 문구, 2026-11 결정)

## 제거된 기능 (다시 넣지 말 것)
- 네이버 로그인
- 캐릭터·유명인 AI 자동 검사 (변호사 자문 예정)
- "모자라요" 부족 접수 버튼 → 네이버 톡톡 안내 문구로 대체
- 고객용 배경 제거 안내

## 저장소 설계 초안
- 파일 저장소(객체 스토리지): 사진 원본(보관 기간 후 자동 삭제), 3D 모델, 설명서 PDF
- 일반 DB: 시안, 동의 기록(약관 버전·시각 포함, 삭제 금지), 주문 코드, 주문, 블럭 재고, 설정(가격·횟수)
- Redis(선택): 하루 무료 횟수 카운터

## 관리자 화면 (1차 범위)
주문 목록·코드 검증, 작업지시서(색상별 개수·무게 환산), QR 안내지 인쇄. 재고·통계는 2차.

## 1차 개발 범위 제안
1. 시연 페이지(`docs/demo.html`)의 고객 화면을 실제 웹사이트로
2. 사진 업로드 + 평면 시안 생성
3. 주문 코드 발급·저장 + 관리자 주문 검증 화면
4. 무료 횟수 제한 (쿠키 + IP)
5. 입체(3D API)는 업체 선정 후 2차

## 미결정·확인 대기
- 변호사 자문: 개인정보 동의 방식(계약 이행용 정보는 동의 없이 고지만으로 가능한지), 만 14세 확인 필요 여부, 캐릭터 모양 재현 가능 여부, 약관
- KC 안전확인: 시험기관 견적, 36색을 한 모델로 신고 가능한지
- 네이버 판매자센터: 외부 사이트 연동, 주문 코드·추가상품 수량 방식, 주문제작 상품 설정
  - 외부 링크: 공식 정책 미확인. 2025-05부터 스마트에디터의 iframe·단축 URL 제한이 시행됐다는 자료만 있음 → 단축 URL 금지, 사이트로 가는 경로는 버튼 이미지·주소 텍스트·QR을 모두 넣는다 (상세페이지 상단과 하단)
- 3D 생성 API 업체, 판매가·블럭 단가, 사진·PDF 보관 기간
- 하루 전체 AI 비용 상한 (예: 3만 원) 도입 여부: 추가 검토 필요. 검토 전까지 구현하지 않는다
- 사업자등록, 통신판매업 신고, '브릭라이즈' 상표 출원

## 폴더
- `docs/` 시연 페이지, 흐름도, 회의 요약 이미지
- `prototype/` 브릭화 파이썬 프로토타입
  - `cube.py`: GLB → 1x1 큐브 배치 (현재 방식). `python3 cube.py model.glb 100` (100 = 최대 mm)
  - `pal39.py`: 39색 팔레트 (판매 사진에서 측정한 임시 RGB, 샘플 실측 후 교체)
  - `brickify.py`, `brickify2.py`: 이전 레고형 브릭·플레이트 배치 (참고용)
  - 필요 패키지: trimesh, numpy, scipy, scikit-image
- `assets/` 샘플 사진, TRELLIS.2 결과 GLB, 디폼블럭 색상표·규격 이미지
- `marketing/` 네이버 스마트스토어 홍보물 (상세페이지·대표 이미지, 등록 문구 초안). 미확정 값은 빨간 점선 표시

## 역할 분담 (2026-11 추가)
- 이 폴더(`LetsGo2/Brickrise`)는 웹 홈페이지 개발용. Claude Code는 웹(고객 화면·관리자 화면·서버)을 맡는다
- Image → 3D, 3D → Brick 생성형 AI 파이프라인은 타 팀원이 별도로 개발 중. 웹에서는 그 결과를 API로 받아 쓰는 형태로 연결하고, 파이프라인 내부는 구현하지 않는다

## 웹 개발 현황 (`web/`)
- Next.js(App Router, TypeScript), Vercel 배포. 구조·실행·배포 방법은 `web/README.md`
- 고객 화면 `src/app/(customer)`, 관리자 화면 `src/app/admin`, 서버 API `src/app/api`, 서버 로직 `src/server`, 공용 `src/shared`
- 저장소: Postgres(Vercel Marketplace의 Neon, `DATABASE_URL`), 사진은 Vercel Blob 비공개. 무료 횟수 카운터도 Postgres에 둔다(Redis 없음)
- 평면 시안은 웹 서버에서 직접 생성 (`src/server/generation`, docs/demo.html 로직 이식)
- 입체 시안은 임시 생성기(실루엣 부풀리기). 생성형 AI·API 규격이 정해지면 `docs/ai-pipeline-interface.md`대로 교체
- 39색 팔레트는 확정 (`src/shared/palette.ts`, 순서 변경 금지)
